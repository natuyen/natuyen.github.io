Why it starts with Markdown

AI writes Markdown. Your team reads it all day.

Specs, backlog breakdowns, review notes, retro reports — more and more of them are drafted as .md by an assistant and then read, checked and diffed by people. Markdown won that job precisely because it is plain text: cheap for a model to produce, clean for git to version, readable without a viewer.

“Readable without a viewer” is where it stops being true. A Garoon spec keeps whole HTML tables on single 5000-character lines. A pull request shows you that the line changed — not which cell, which bullet, which sentence. And a .md link on GitHub does not even serve the file; it serves a web page.

So the two tools below come first. They turn a .md file — and a .md diff — back into something a human can actually read.

Flagship tool 1 of 2 — Markdown Text Viewer

any .md / .txt link

Read the spec, not the markup.

Right-click any .md or .txt link and it opens as a real document: headings, tables, images, code — rendered instantly, with nothing sent anywhere.

  • Never lose your place. The table of contents opens on every run and follows your scrolling.
  • Switch files without going back. 📚 N files lists every document on the page you came from; only the one you pick is fetched.
  • Copy what you need. Hover a code block for a Copy button.
  • Actually see the screenshots. Click an image for a full-screen view.
  • Reads the way GitHub reads it. Two-space line breaks stay breaks, and escaped text such as HKEY\_LOCAL\_MACHINE comes out as written — no stray backslashes, no sentences run together.
  • Long specs stay navigable. Home / End, a ↑ Top button, keyword search.

Contents on the left — drag the divider to give the text more room.

A .txt stays a .txt

Plain files open in plain-text mode: line breaks, indentation and characters like * exactly as written, with an editor-style gutter. Copy the file and you get the file — the numbers stay behind.

Nothing leaves your browser. Files are fetched the way your browser already fetches them, and rendered on the spot — nothing is uploaded, there is no service to sign into and no token to paste. The screenshots embedded in a document appear as well, instead of the broken-image icons you get elsewhere.

Retro reports and logs keep their alignment.

Where you find it — two ways in

The first entry opens the file you clicked. The second jumps straight to the 📚 list, for pages whose file names are not links to the file at all.

Flagship tool 2 of 2 — Git Markdown Viewer

GitHub pull request

See what changed — not where the HTML moved.

Garoon spec files keep whole HTML tables on single 5000-character lines. GitHub highlights the entire line and you are left hunting. G&K Tools renders both versions side by side and marks the difference on the content itself — the cell, the bullet, the sentence.

  • Paired labels, so you can see what replaced what. The two halves of one change are 2-o on the left and 2-n on the right — click either and it jumps to its counterpart. A change with nothing opposite it is greyed, so “edited” never looks like “added”.
  • Both sides stay level. An added or deleted block leaves blank space opposite it, so a change is always beside its counterpart instead of beside unrelated text — in both viewing modes.
  • Line numbers, and click to pick a line. Each side numbers its own lines; click the text to highlight the whole line across both panes, or a number to highlight just that side.
  • “Changes only”, with context. Untouched content collapses, but neighbouring rows stay — and both sides keep the same context.
  • One button, no menu. A floating 📄 View .md diff (N) appears on any pull request that touches a .md file.
  • Reads what the PR proposes. Files open at the pull request’s head commit, not at main.

Paired labels tie the two halves of a change together, blank space keeps the panes level, and a picked line lights up across both sides. ↑ ↓ walk you through the changes, file by file.

Where you find it

Offered only when the pull request really changes a .md file — the page is scanned before the menu is shown.
